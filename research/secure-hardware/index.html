Research / Secure Hardware/Software Co-Design

Secure Hardware/Software Co-Design

Quantifying and improving the security–performance trade-offs of hardware and trusted execution environments.

Security features change how hardware performs, and performance features can open security holes. We study program–architecture interactions to quantify security in hardware/software co-design, evaluate trusted execution environments, and make security a first-class objective in architecture design-space exploration.

Open questions

  • What does security cost in performance for trusted execution environments on CPUs and GPUs, and where does the overhead come from?
  • How can we benchmark proprietary applications inside TEEs without exposing them?
  • Can hardware signals such as performance counters reliably detect attacks, and when do they mislead?

Current projects

Performance–security trade-offs in TEEs

Characterize and model TrustZone, SGX, and confidential-computing overheads, including confidential LLM inference.

Privacy-preserving benchmarking

Tools that generate representative benchmarks for proprietary applications to evaluate trusted execution.

Security-aware design-space exploration

Treat security and verification cost as first-class objectives when exploring microarchitecture designs.

Explainable ML for secure co-design

Interpretable models of program–architecture interactions that lead to vulnerabilities.
